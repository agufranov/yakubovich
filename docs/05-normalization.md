# Нормализация и классификация лотов

## Задача

Лоты приходят в виде свободного текста и бывают чем угодно: «Легковой автомобиль
ХЕНДЭ SANTA FE, 2015 г/в», «1/2 доля в праве общей долевой собственности на квартиру»,
«Самоходная машина: мини-трактор KIOTI CK22H», дебиторская задолженность, доля в ООО,
самолет, промышленная установка. Из этого нужно получить единый фильтруемый каталог.

## Принцип: сначала дешевое, потом дорогое

Три уровня, каждый следующий применяется только к тому, что не разобрал предыдущий.

```
   1. Структурные поля источника     ← бесплатно, точность ~100%
             ↓ не разобрано
   2. Правила и регулярные выражения ← дешево, точность высокая на якорях
             ↓ не разобрано
   3. LLM-извлечение                 ← дорого, только на остатке, с кэшем
```

Соблазн начать сразу с третьего пункта велик и его надо прямо назвать ошибкой: он
дороже, медленнее, недетерминирован и хуже там, где первые два уровня работают идеально.

### Уровень 1 — структурные поля

ГИС Торги отдает готовый `category` из госклассификатора и массив `characteristics`
с нормализованными атрибутами (`vin`, `carMarka`, `mileage`, `cadastralNumberRealty`,
`totalAreaRealty`…). Для этих лотов извлекать нечего — только замапить коды в наш
справочник. Это делает ГИС Торги ещё и **источником эталонной разметки**: на нем
проверяется точность уровней 2 и 3, потому что для одних и тех же лотов есть и текст,
и правильный ответ.

Такой размеченный корпус получить бесплатно — редкая удача, использовать обязательно.

### Уровень 2 — правила и якоря

Русские описания лотов удивительно шаблонны. Надежные якоря:

| Что | Как достается |
|---|---|
| VIN | `[A-HJ-NPR-Z0-9]{17}` с проверкой контрольного разряда |
| Кадастровый номер | `\d{2}:\d{2}:\d{6,7}:\d+` |
| Год выпуска | `(19\|20)\d{2}\s*г(\.\|/)?в` |
| Площадь | `(\d+[.,]?\d*)\s*(кв\.?\s*м\|м2\|м²)` |
| Пробег | `(\d[\d\s]*)\s*км` |
| Доля | `(\d+)/(\d+)\s*дол\|доля в праве` |
| Госномер | `[АВЕКМНОРСТУХ]\d{3}[АВЕКМНОРСТУХ]{2}\d{2,3}` |

Категория определяется словарями по ключевым словам («автомобиль», «квартира»,
«земельный участок», «дебиторская задолженность», «доля в уставном капитале»). На
верхнем уровне категорий (8-10 штук) это дает высокую точность — русский язык описаний
лотов достаточно формален.

Кириллица требует внимания: буквы в госномерах и марках смешиваются с латиницей
(`ХЕНДЭ` / `HYUNDAI`, `А` кириллическая и `A` латинская). Нормализация — обязательный
шаг перед матчингом, иначе склейка по номерам молча не сработает.

### Уровень 3 — LLM на остатке

Применяется к лотам, которые правила не разобрали: сложные, составные («имущественный
комплекс из 14 позиций»), редкие типы.

Экономика, чтобы решение принималось по числам, а не по ощущению: при ~500 новых
неразобранных лотов в день и ~2000 входных токенов на лот это ~1 млн токенов в сутки.
На Haiku 4.5 — порядка доллара в день. То есть **это не значимая статья расходов**,
если и только если LLM не гоняется по всему потоку, а работает на остатке и результат
кэшируется по хешу текста.

Требования к использованию:

- строгий JSON-выход по схеме, валидация, отказ вместо угадывания;
- результат пишется с `source='llm'` и `confidence<1` ([04-data-model.md](04-data-model.md));
- батчинг; повторный разбор того же текста не оплачивается дважды;
- точность меряется на эталонном корпусе ГИС Торги, а не на глаз.

## Верхний уровень категорий

Достаточно 8-10 категорий, чтобы закрыть почти весь спрос. Дробить глубже — на этапе,
когда появятся данные о том, что реально ищут.

```
Транспорт          — легковые, грузовые, спецтехника, водный, воздушный
Недвижимость       — квартиры, дома, нежилые, доли
Земля              — участки всех назначений
Оборудование       — станки, техника, товарные остатки
Бизнес             — доли в УК, предприятие как комплекс
Права требования   — дебиторская задолженность
Прочее             — всё остальное
```

## Что нормализовать обязательно

**Регион.** Приводить к кодам субъектов РФ. Это фильтр номер один: имущество смотрят
рядом с собой. ГИС Торги дает `subjectRFCode` готовым, у ЭТП — разбирать из текста
адреса.

**Цена.** Только `numeric`, только из точных строковых полей. См. [грабли](research/grabli.md).

**Даты и часовые пояса.** Лоты по всей стране, у ГИС Торги есть `timezoneOffset`.
Хранить в UTC, показывать в поясе лота. «Прием заявок до 12:00» без пояса — это
ошибка на 9 часов между Калининградом и Камчаткой, то есть пропущенные торги
у пользователя.

**Тип торгов.** `auction` / `public_offer` / `competition`. От этого зависит вся
логика цены: у публичного предложения цена падает по графику, и это отдельная механика.
