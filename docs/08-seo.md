# SEO и трафик

## Почему это главный раздел продуктовой части

Конкуренты закрывают лоты подпиской. Их карточки либо не индексируются, либо
показывают пользователю заглушку. Это оставляет открытой всю поисковую выдачу по
запросам вида «купить квартиру с торгов Казань», «арестованные автомобили аукцион».

Открытые карточки + SSR — это канал привлечения, который не требует бюджета и
работает годами. Для проекта, который делается дешево, это не «одна из активностей»,
а основной способ получить аудиторию.

## Что индексируем

**Карточка лота.** Уникальный текст, цена, фото, регион, даты, ссылка на площадку.
Основная масса страниц.

**Посадочные страницы срезов** — здесь главный объем трафика:

```
/банкротство/автомобили/москва
/банкротство/квартиры/татарстан
/арестованное-имущество/спецтехника
```

Комбинация «категория × регион (× тип торгов)» дает несколько тысяч осмысленных
страниц. Важно: генерировать только те, где реально есть лоты, — пустые страницы-срезы
это классический thin content, за который весь сайт получает понижение. Порог вида
«не меньше 3 активных лотов» и `noindex` для остального.

**Архивные страницы — стратегический актив.** Лот живет 1-3 месяца, потом исчезает
из источника. Страница «Квартира 54 м², Казань — продана за 2,1 млн ₽ (март 2026)»
остается ценной вечно: по ней приходят люди, которые ищут, сколько такое стоит.
Конкуренты архив в основном закрывают. За год накопления это десятки тысяч страниц
с уникальным содержимым, которое невозможно скопировать задним числом.

Отсюда прямое требование к архитектуре: **ничего не удалять, менять статус на
`archived`** ([04-data-model.md](04-data-model.md)) — и начать копить с первого дня,
раньше, чем появится сайт.

## Техническая часть

**Рендеринг.** Next.js SSR/ISR. Карточка активного лота — ISR с ревалидацией порядка
часа, архивная — статика с длинным сроком. Клиентский рендеринг для карточек
недопустим.

**Sitemap.** Сотни тысяч URL не помещаются в один файл (лимит 50 000). Нужен индекс
сайтмапов, разбитый по типу и дате, с честным `lastmod`. Генерировать по расписанию
из БД.

**Микроразметка.** `Product` + `Offer` + `AggregateOffer` на карточках,
`BreadcrumbList` в навигации. Дает расширенные сниппеты с ценой прямо в выдаче — по
такому запросу это заметно поднимает кликабельность.

**Канонические URL.** Один лот на нескольких площадках может дать несколько карточек;
после склейки в `asset` показывать одну и ставить `canonical`. Фильтры и сортировки
в query-параметрах — `canonical` на базовый срез, иначе комбинаторика фильтров
породит бесконечность дублей.

**Скорость.** Core Web Vitals. Главные враги на таком сайте — тяжелые фотографии из
источников. Превью генерируем сами в WebP, отдаем с CDN, оригиналы — по клику.

**Robots.** Закрыть от индексации: фильтрованные срезы с параметрами, страницы
поиска, личный кабинет, страницы с ФИО физлиц ([07-legal.md](07-legal.md)).

## Чего не делать

Не генерировать тысячи пустых страниц «на всякий случай» — это не расширение охвата,
а системное понижение всего домена. Не копировать чужие описания дословно
([07-legal.md](07-legal.md)). Не закрывать карточки регистрацией — это ровно то, что
делает конкурентов уязвимыми, и повторять их ошибку было бы странно.

## Метрики

Индексируемые страницы, доля в индексе, органический трафик по типам страниц,
конверсия «просмотр карточки → переход на ЭТП». Последняя — главная продуктовая
метрика на первом этапе: она показывает, что сайт реально приводит людей к покупке.
