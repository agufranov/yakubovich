# Реестр ЭТП по банкротству: движки и подключаемость

> Источник списка: реестр торговых площадок tbankrot.ru (`/reestr?type=tp`), категория
> «Банкротство» — **49 площадок**. Список сохранен в [tools/probe/etp_list.json](../../tools/probe/etp_list.json).
> Проверка выполнена 2026-08-25 скриптами [tools/probe/](../../tools/probe/).

## Главный вывод

**Гипотеза об общих white-label-движках подтвердилась.** Площадки не независимы:
значительная часть работает на одинаковом коде с точностью до URL. Один коннектор
покрывает 14 площадок сразу.

При этом «49 открытых API» — не про эту нишу. Ни у одной площадки нет публичного
REST. Везде разбор HTML, у крупнейшего семейства — с постбэками ASP.NET.

## Доступность

Из 49 площадок на главной странице ответили `200` — **45**. Недоступны на момент
проверки: «Property Trade» (502), Альфалот (429 — троттлинг), ТендерСтандарт (404),
ЭТП «Югра» (ошибка соединения).

### URL — идентичны на всех 14

```
/public/auctions-all/            аукционы
/public/public-offers-all/       публичные предложения   ← ключевая механика продукта
/public/contests-all/            конкурсы
/public/purchases-all/           закупки
/public/{раздел}/lots/view/{id}/ карточка лота
```

**Замыкающий слэш обязателен.** Без него — 404. На это уже наступили: первая проверка
дала «0 из 13 совпадений» ровно из-за срезанного слэша.

По 20 лотов на страницу.

### Карточка лота

Обычная HTML-таблица «подпись → значение», разбирается устойчиво. Содержит:

| Поле | Ценность |
|---|---|
| **Номер сообщения в ЕФРСБ** | **Канонический сквозной ключ** |
| **Классификатор ЕФРСБ** | Готовая нормализованная категория («Автомобили») |
| Повторные торги (да/нет) | Связывание цепочек торгов по одному объекту |
| Начальная цена, шаг (% и руб.) | |
| Даты начала/окончания приема заявок, дата проведения | |
| Статус | |
| Размер и порядок внесения задатка, реквизиты счета | |
| Наименование, дополнительные сведения, порядок ознакомления | |
| Документы | Ссылками |

Два поля меняют план по сравнению с исходным:

**«Номер сообщения в ЕФРСБ» на карточке ЭТП** дает канонический идентификатор лота
**без доступа к самому ЕФРСБ**. Это ровно тот ключ, ради которого планировался платный
веб-сервис Федресурса. Для дедупликации между площадками и для склейки повторных
торгов его достаточно.

**«Классификатор ЕФРСБ»** — нормализованная категория из государственного справочника,
как `category` в ГИС Торги. Уменьшает объем работы по классификации
([../05-normalization.md](../05-normalization.md)).

### Чем неудобен: пагинация на постбэках

Движок — классический ASP.NET WebForms. Переход по страницам идет через
`__doPostBack` с `__VIEWSTATE` (36 вызовов на странице, форма `method="post"`).
Обычным GET по номеру страницы обойти список нельзя.

Коннектор обязан:

- держать сессию, вытаскивать `__VIEWSTATE` и `__EVENTVALIDATION` из текущей страницы;
- отправлять POST с этими полями и целью постбэка для следующей страницы;
- переполучать их с каждой страницы — они меняются.

Это медленнее и хрупче, чем REST, но **работа делается один раз на все 14 площадок**.
Именно поэтому семейство iTender — первая цель, а не самая крупная одиночная площадка.

### Статус подключения (2026-08-26)

**Коннектор написан и работает**: `packages/connector-etp-itender`, фабрика на
площадку (`itender-<код>`), сбор — `npm run ingest:etp`. Живым прогоном на
bankrupt.centerr.ru подтверждено:

- листинги и карточки отвечают по **GET** (постбэк нужен только пагинации);
- `__VIEWSTATE` пустой — состояние в `__CVIEWSTATE` (свое поле движка) и в
  сессии, поэтому обязательны куки; в постбэк пересылаются ВСЕ hidden-поля;
- пейджер — числовые ссылки окна по 10 + `>>` в следующее окно; обход
  последовательный, цель постбэка берется из ссылки с номером нужной страницы;
- кодировка UTF-8; деньги с NBSP-разделителями тысяч; даты `dd.MM.yyyy HH:mm`
  **без указания пояса** (принято допущение МСК — проверить!);
- документы — прямые ссылки `/public/attachments/file/{id}/{имя}`.

## Порядок подключения

| Очередь | Что | Почему |
|---|---|---|
| 1 | iTender (14 площадок) | Лучшее отношение результата к трудозатратам |
| 2 | Крупные одиночки: Сбербанк-АСТ, РАД, Фабрикант, МЭТС | Объем лотов, а не число площадок |
| 3 | Группы `/etp/trade/list.html` и `/lots` (по 3) | Снова эффект белого лейбла |
| 4 | Остальные одиночки | По мере роста, каждая — отдельные постоянные расходы |

## Что проверить при подключении

- Реальные объемы лотов по площадкам — счетчиков в реестре нет, считать самим.
  Приоритет должен строиться по лотам, а не по числу площадок.
- Отдают ли iTender-площадки **график снижения цены** для публичного предложения
  структурно, или его придется разбирать из текста условий.
- Живы ли ЭТС24 и «Заказ РФ» (пустая выдача на момент проверки).
- Альфалот отдал `429` — там нужен щадящий режим с самого начала.
