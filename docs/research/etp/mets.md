# МЭТС (m-ets.ru): разведка и подключение

> Проверено запросами 31.08.2026. Все цифры и адреса ниже воспроизводимы:
> фикстуры реальных ответов лежат в
> [packages/connector-etp-mets/test/fixtures/](../../../packages/connector-etp-mets/test/fixtures/).

ООО «МЭТС», Орел. Крупная одиночная площадка по банкротству, своя разработка
(Java, JSESSIONID), к семействам движков не относится — коннектор отдельный.

## Зачем именно она

Заказчик просил начать с автомобилей. МЭТС для этого — лучший из проверенных
источников, и не только по объему:

| Что дает | Почему это важно |
|---|---|
| **3 104 банкротных лота «Легковой автомобиль»** (счетчик выдачи, 31.08.2026) | Объем есть. Для сравнения: у всего семейства iTender объем еще не посчитан |
| **Свойства машины отдельными полями**: марка, модель, год, пробег, мощность, КПП, привод, двигатель, **VIN** | VIN — ключ к рыночной цене (фаза E LOTUM). Разбирать из текста описания не нужно |
| **График снижения цены — таблицей** | Ключевая фича продукта. У iTender вопрос «структурно или текстом» до сих пор открыт, здесь ответ — структурно |
| **Должник, арбитражный управляющий, организатор — отдельными полями**, с ИНН, СРО и **ссылкой на карточку лица в ЕФРСБ** | Те самые «сущности». Ссылка дает сквозной идентификатор лица между площадками |
| **Номер дела о банкротстве, арбитражный суд, дата введения процедуры** | Ключ процедуры: одно дело — много лотов, часто по разным торгам |
| Идентификационный номер торгов на ЕФРСБ | Тот же канонический ключ, что и у iTender |

## Как устроен доступ

### robots.txt разрешает не всё

```
User-agent: *
Disallow: /*                      # всё закрыто, дальше точечные исключения
Disallow: *page=*                 # ПАГИНАЦИЯ ЗАПРЕЩЕНА ЯВНО
Allow:    /*-                     # карточки лотов /{торги}-{лот} — разрешены
Allow:    /sitemap*               # карты сайта — разрешены
Allow:    /search?q=*&sp=7qr7$    # только SEO-адреса поиска
Sitemap:  https://m-ets.ru/sitemap.xml
```

Отсюда решение: **обход идет по sitemap, а не по выдаче поиска.** Это не только
вежливо, но и удобнее — см. ниже.

Карточки лотов при этом отдают `<meta name="robots" content="noindex, nofollow">`
— площадка не хочет индексации своих карточек поисковиками. Читать это как запрет
на доступ нельзя (`Allow: /*-` говорит обратное), но факт для docs/07 значимый:
на наши страницы это не переносится, у нас свой текст и своя ответственность.

### Sitemap — штатный канал discover

```
/sitemap.xml                       индекс, 56 карт
  /sitemap/active_lots.xml         10 000 активных лотов
  /sitemap/active_lots_02.xml      остаток активных
  /sitemap/completed_lots_*.xml    завершенные, десятки файлов
```

Каждая запись:

```xml
<url>
  <loc>https://m-ets.ru/180235-1</loc>
  <lastmod>2026-08-30</lastmod>
  <changefreq>daily</changefreq>
</url>
```

`lastmod` — готовый **отпечаток для discover**: изменился — перекачиваем карточку,
не изменился — не трогаем. Два запроса на весь обход активных лотов вместо сотен
страниц выдачи. Коннектор сортирует по `lastmod` убыванием, чтобы свежее шло
первым и `stopAfterUnchangedPages` обрывал прогон на неподвижном хвосте.

Ограничение: `lastmod` с точностью до суток. Два изменения за день видно как
одно; страхует sweep и сравнение контентного хеша карточки.

### Поиск: параметры едут в base64

Форма поиска НЕ отправляет поля как есть. JS собирает из них JSON, сортирует
ключи, кодирует в base64 без хвостовых `=` и кладет всё в один параметр:

```
/search?q=eyJpc2JhbmtyIjoib24iLCJzZWFyY2hfY2F0ZWdvcnkiOiIxIn0
        = {"isbankr":"on","search_category":"1"}
```

Обычные GET-параметры (`/search?search_category=1`) движок **молча выбрасывает**
и отвечает `308` на голый `/search` — ровно тот случай, о котором CLAUDE.md.
Фильтр проверен подачей бессмысленного значения: `search_category=99999` дает
«Ничего не найдено», значит фильтр работает, а не игнорируется.

Полезные поля формы (пригодятся, когда понадобится точечный срез):

| Поле | Что делает |
|---|---|
| `search_category` | категории через запятую; `1` — легковой автомобиль, `3` — коммерческий транспорт и спецтехника, `4` — мото, `12` — с/х техника |
| `isbankr` / `iscom` | банкротные / коммерческие торги |
| `isauk` / `ispub` | аукцион / публичное предложение |
| `xregion[]` | регионы, коды совпадают с автомобильными |
| `auto_brand_id`, `auto_model_id`, `autoyear_ot/do` | марка, модель, год — у площадки свой справочник машин |
| `cena_tek_ot/do`, `proc_snij_ot/do` | текущая цена и процент снижения |
| `debtor`, `arb`, `org` | должник, арбитражный управляющий, организатор — поиском по ИНН |
| `stat[]` | статусы: 0 объявленные, 1 прием заявок, 6 прием завершен, 2 проведение аукциона, 7 подача предложений завершена, 8 подведение итогов, 3 завершены, 4 отменены, 5 приостановлены |

Пагинация — `&page=N`, по 20 лотов, и она запрещена robots.txt. В коннекторе
этот путь есть (`--via-search`), но он не по умолчанию и печатает предупреждение:
решение обходить выдачу постранично принимает человек, а не код.

Замечено попутно: `foto=on` на число результатов не влияет — поле молча
игнорируется. Проверять фильтры подачей бессмыслицы стоит каждый раз.

## Карточка лота

Адрес: `/{номер торгов}-{номер лота}`, например `/231205-1`. Он же `externalId`.

Верстка однородная:

```html
<div class="lot-info-item">
  <div class="title">Идентификационный номер (VIN)</div>
  <div class="value">Z94K241CBNR341900</div>
</div>
```

Блок без `value` — заголовок раздела. **Разделы обязательны для разбора**: поля
«ФИО» и «ИНН» встречаются и у должника, и у управляющего, и у организатора, и
различить их можно только по разделу.

### Грабля: в торгах несколько лотов — страница рендерит их все

Страница `/215458-2` содержит блоки ВСЕХ лотов этих торгов, каждый в своем
`<div class="generalview-container" data-lotNumber="N">`. Разбор по всему
документу молча выдает второму лоту характеристики первого — что и произошло на
первом живом прогоне: 215458-1 и 215458-2 получили один VIN на двоих.

Разделение такое:

- **внутри контейнера лота**: название, статус, цены, график снижения, VIN и
  свойства машины, категория (`data-categories`), регион (`data-regionId`);
- **ниже контейнеров, общее на все лоты**: сведения о торгах и датах, должник,
  управляющий, организатор, номер дела, документы, номер торгов на ЕФРСБ.

Коннектор ищет поля лота только в его контейнере, а поля торгов — по документу.

### Что берем и чего не берем

Берем: см. таблицу в начале. Плюс обременения, порядок ознакомления, документы
ссылками (файлы не храним — решение №4).

**Не берем СНИЛС должника**, хотя площадка его показывает. Для поиска и склейки
сущностей он не нужен, а 152-ФЗ по должникам-физлицам — открытый риск проекта
([docs/07-legal.md](../../07-legal.md), «минимизация»). Тест на это есть: он
проверяет, что поле на карточке присутствует, а в нашем лоте — нет.

## Прочие мелочи источника

- Кодировка UTF-8, разделители тысяч — неразрывные пробелы.
- Время явно московское: площадка пишет «17:48 (МСК)» в шапке. В отличие от
  iTender, где пояс пришлось принимать допущением.
- Снятая карточка отвечает `200` обычной страницей — проверяем содержимое,
  а не код ответа.
- TLS обычный (Let's Encrypt), бандл Минцифры не нужен, но и не мешает: клиент
  добавляет российские корни К системным, а не вместо них.
- Изображения лотов: `<img itemprop="image">`, заглушка `no-image.png`
  отфильтровывается. **Лота с настоящими фото в фикстурах пока нет** — разбор
  галереи написан по разметке и живьем не подтвержден.

## Статус подключения

`packages/connector-etp-mets`, sourceCode `etp-mets`, `etpCode` — `mets`.

```
npm run ingest:mets -- --pages=3 --limit-cards=100     # штатно, по sitemap
npm run ingest:mets -- --sweep --limit-cards=200       # уборка статусов
npm run ingest:mets -- --via-search --vehicles --pages=10   # см. robots.txt выше
```

Живым прогоном 31.08.2026 подтверждено: sitemap читается, карточки разбираются,
ошибок http/parse — ноль. В базе лоты с графиком снижения (до 20 периодов),
должником-физлицом и должником-юрлицом, залоговым кредитором.
